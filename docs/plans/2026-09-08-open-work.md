# 2026-09-08 - Open work: the accuracy gaps and the consolidation

The standing list after the NInfer accuracy session. Two quality gaps, the
provider consolidation, and the adjacent debt that surfaced. Ordered by value;
the GPU-bound items are grouped so the engine gets loaded once.

## P0 - Quality gaps (GPU-bound, do together while the engine is up)

### G2. Long-context quality: needle `--no-swap` mode, then the probe

The decisive open claim. Decode speed is proven flat to 262K; whether the
model still *retrieves* at 200K is unmeasured. `llmc bench needle` exists and
works on llama.cpp presets; the tokenizer fallback (776fa17) covers engines
with no `/tokenize`.

The blocker is structural: needle sweeps ctx by registering an ephemeral
`needle-<ctx>` preset and lock+switching the proxy to it. NInfer is
single-resident and cannot hot-swap; the ephemeral preset's model_id is not a
loadable artifact, so the swap timed out and tore the engine down
(2026-09-08, and it collided with a concurrent eval on the same engine).

Build a `--no-swap` mode: probe the already-resident preset at its configured
`max_context` across depth fractions, skipping the ephemeral/lock/switch block
entirely. Reuse the 776fa17 tokenizer fallback. ~30 lines in needle.py plus a
CLI flag and a test. Then run:

```
# in the bench-eval image (has transformers), against host.docker.internal
llmc bench needle --preset qwen38-ninfer --no-swap \
    --depths 0.05,0.25,0.5,0.75,0.95 --runs 2
```

Good loop task (the needle loop pattern proved itself). SERIAL only - never
alongside an eval. Spec lives in `/tmp/needle-task.md`'s successor; the
runbook has the full note.

### G1. The 6.2% slow tail

In the spike's 336-request validation run, 6.2% of requests decoded below
100 tok/s (worst 33.9, a 4x collapse) against a ~140 tok/s baseline at that
context, clustered at 66-72K ctx with substantial outputs. Ruled out: MTP
draft acceptance (drops only 65.6% -> 56.5% on those requests - not enough).
Unexplained; candidate causes are fp8 KV pressure, a long-prompt x long-output
interaction, or an NInfer scheduler bug.

Chasing it: pull the slow requests from the proxy log, characterize what they
share (ctx bucket, output length, effort), reproduce one deterministically,
then either find a config knob or file it upstream with a repro. GPU-bound,
half a day, uncertain payoff (could be a knob, could be an engine bug you
can't touch). Lower priority than G2 because the payoff is uncertain.

### Churn stability (the spike's open p6)

Distinct from G1: whether sustained agentic traffic degrades decode over
session age. Cheapest signal: `llmc bench tasks --presets qwen38-ninfer
--runs 3` back-to-back and compare per-task wall time across runs; a rising
wall time across runs is the churn signature. Can run in the same GPU window
as G1/G2.
